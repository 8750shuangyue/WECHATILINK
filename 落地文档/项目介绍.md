## 一、一句话简介

世宠绿护（Sekai PetPlant）是一套以 **AI Agent 为核心**、面向宠物主人与绿植养护人群的 **智能护理 Web 平台**。用户以自然语言和图片对话为入口，即可完成养护问答、AI 识图诊断、护理档案与提醒、私有知识库检索问答、商城库存、社区分享与每日简报等全流程操作。

---

## 二、简明版介绍（约 300 字）

世宠绿护（Sekai PetPlant）是一个面向宠物主人和植物养护人群的一站式 AI 护理平台。系统以浏览器 Web 端为唯一入口，采用「AI Agent + 工具调用 + 长期记忆 + 检索增强生成（RAG）」的技术路线：用户用文字、语音或图片与 AI 对话，即可获得宠物喂养与植物养护的专业建议，上传照片识别植物病虫害与宠物皮肤病，建立宠物 / 绿植成长档案与用药、疫苗台账，设置浇水、喂药、疫苗等护理提醒并通过浏览器推送到期通知，还能查询附近宠物医院、植物医院与园艺店。平台内置可上传、可分块、可向量化检索的私有知识库，让 AI 基于用户自己的资料作答，并通过用户 / 会话隔离、检索审计与安全鉴权保障数据边界。除护理主链路外，平台还整合了商城、库存、社区、成长时间线、每日简报与数据观测等业务模块，形成从「问、拍、记、提醒、找服务」到「看数据」的完整闭环。

## 三、项目定位

### 1. 产品定位

一个以 **AI Agent 为核心**的垂直场景一站式智能护理 **Web 平台**。它既不是通用聊天机器人，也不是单纯的记录工具，而是把「问答、识别、记录、提醒、服务查询」串成一条完整链路的护理助手：用户遇到问题直接开口或拍照，系统负责给出建议、存档留痕、到期提醒，并在需要时把用户导向线下服务。

### 2. 场景定位

聚焦 **宠物护理** 与 **植物养护** 两个高关联的日常养护场景，而不是覆盖泛生活服务。两者在养护逻辑上高度相似——都需要周期性操作、都需要识别异常、都需要长期记录——因此共用同一套对话、记忆、知识库与提醒底座，避免为两个场景各做一套系统。

### 3. 用户定位

| 维度 | 内容 |
| --- | --- |
| 主要用户 | 养宠家庭与个人、家庭绿植与阳台种植爱好者、园艺种植新手 |
| 典型诉求 | 缺少专业知识、养护时间碎片化、需要长期坚持周期性动作 |
| 使用场景 | 日常养护咨询、异常排查、周期提醒、购后养护指导、附近服务查询 |

用户特征决定了产品强调「低门槛」与「少操作」：以对话替代表单，以提醒替代记忆负担，以拍照替代专业仪器。

### 4. 技术定位

技术路线锁定为 **「AI Agent + 工具调用 + 长期记忆 + 检索增强生成（RAG）」**：

- AI Agent 负责理解意图、编排多步任务与生成回答；
- 工具调用把「能查、能算、能生成、能落库」的真实能力接入模型，让回答有事实依据而非凭空生成；
- 长期记忆保证跨会话的连续养护体验；
- RAG 让模型基于平台私有资料作答，而不是依赖通用先验知识。

工程上定位为 **可运行、可评测、可观测** 的生产级项目，而非功能演示：有独立的自动化评测基线、有检索审计链路、有向量数据治理与备份恢复流程。

### 5. 边界与不做

- **端形态**：专注 Web 端，不提供 App、小程序或公众号入口（微信 ILink 与公众号接入已于 2026-08-15 移除）；
- **能力边界**：输出养护建议与风险提示，不替代执业兽医的临床诊断与处方，涉及疑似重症时引导线下就诊；
- **数据边界**：业务数据按用户归属隔离，公共知识库与用户私有资料分层管理。

### 6. 差异化

| 常见方案 | 世宠绿护的差异 |
| --- | --- |
| 通用 AI 助手：答得泛、不记得、不能落地操作 | 垂直养护场景 + 工具调用，答案可查、可记、可执行 |
| 纯记录类工具：只存不管，用户仍要想「该干什么」 | 记录与提醒联动，到期主动推送 |
| 纯问答类应用：问完即走，无长期上下文 | 持久化记忆 + 私有知识库，越用越贴合用户 |
| 单场景应用：宠物与绿植各用一套 | 两场景共用一套 AI 底座，维护成本低、体验一致 |

## 四、项目背景与用户痛点

宠物与绿植养护的核心困难集中在四个高频场景：

| 痛点 | 典型表现 | 平台对策 |
| --- | --- | --- |
| 不会养 | 不知道该浇多少水、喂什么粮、怎么施肥 | AI 对话即顾问，结合私有知识库给出针对性建议 |
| 不懂病 | 叶片发黄、宠物皮肤异常，不知是病还是养护问题 | 拍照上传即识别，输出可能病因与处置建议 |
| 容易忘 | 浇水、喂药、疫苗周期难以长期坚持 | 定时提醒 + 浏览器 WebPush 到期推送 |
| 找不到服务 | 紧急情况不知道最近的宠物医院 / 植物医院在哪 | 一问即导航，返回附近门店并附地图链接 |

平台把上述能力收敛到同一个 AI 助手里，避免用户在多个 App、群聊和搜索页面之间反复切换。

## 五、核心功能

### 1. AI Agent 智能助手

以 Spring AI 工具调用和 SSE 流式对话为核心，前端呈现打字机式实时输出：

- **正式流式对话**：读取持久化会话历史与摘要，完整回答后保存消息并异步写入对话向量；
- **护理问答**：复用同一套记忆契约，并额外执行 RAG 知识库检索；
- **工具对话**：模型可自主选择并顺序调用多个工具（例如「查杭州天气 → 生成西湖风景图」），工具结果自动回填上下文；
- **语音输入**：浏览器录音经转码后调用语音识别，识别结果自动填入输入框；
- **多模态输出**：图片分析、图片生成 / 编辑、文档解析、语音合成结果直接渲染在对话流中。

### 2. 工具调用体系

系统维护两套可被 Agent 调用的工具，全部带 trace 记录并落库统计：

- **Spring AI `@Tool` 方法 24 个**，覆盖 8 类能力：实时天气、图像多模态、文档分析、语音合成、联网搜索、附近服务、时间查询、护理与健康管理；
- **自研 `BaseTool` 实现 8 个**：天气、文件分析、图像分析 / 编辑 / 生成、语音合成、网页搜索、附近服务。

每次调用记录工具名、参数摘要、耗时与结果状态，供数据观测面板统计调用排行与趋势。

### 3. 记忆与 RAG 知识库

- **对话记忆**：会话与消息持久化，采用「窗口截断 + 超阈值自动语义摘要」控制上下文成本，长对话不丢关键信息；
- **文档知识库**：支持上传 `txt` / `md` / `json` / `csv` / `log` / `pdf` / `docx`，自动分块、向量化并存入向量库，对话时按相似度检索 Top-K 片段注入提示词，让 AI 基于私有资料作答；
- **用户 / 会话隔离**：对话记忆同时校验用户与会话归属，公共知识库按来源标识对所有用户可见，无法确认归属的历史数据默认不可读写；
- **检索审计**：每次检索记录查询哈希、检索范围、阈值、命中数与耗时，不保存查询明文和文档正文，审计失败不阻断回答。

### 4. 智能护理中心

- 宠物 / 植物档案的新建、编辑与删除；
- 护理记录：浇水、喂药、疫苗等日常操作留痕；
- 护理提醒：支持每日 / 每周 / 每月重复，到期通过浏览器推送；
- AI 识图诊断：植物病虫害与宠物皮肤病两类识别，诊断历史可回看；
- 多轮护理问答：围绕喂养、毒性、疾病等养护问题连续追问。

### 5. 图片中心与媒体管理

AI 生成的图片、语音音频与上传的分析图按用户归档，支持按类型筛选、预览放大与删除；媒体文件统一存放并通过鉴权路径访问。

### 6. 业务功能模块

- **商城**：商品浏览、商品发布与分类管理；
- **库存**：出入库、库存盘点与低库存预警；
- **社区**：发帖、评论、点赞与标签筛选；
- **成长时间线**：记录里程碑，支持自动打点与 AI 小结；
- **每日简报**：每天定时生成养护简报并推送；
- **数据观测**：展示平台概览、工具调用排行与调用趋势。

### 7. 账号与安全

- 注册、登录、登出，基于 Session 会话，密码加密存储；
- 统一鉴权拦截：接口与静态资源需登录，未登录返回标准 401；
- Session Cookie 开启 `HttpOnly` 与 `SameSite`，生产环境可开启 `Secure`；
- 登录失败按 IP + 用户名限流，注册字段做格式与长度校验；
- CORS 使用显式来源白名单，写操作校验请求来源；
- 上传入口统一做大小、扩展名与文件内容校验，图片使用服务端重命名；
- 业务数据按用户归属隔离，档案、记录、提醒、图片均校验归属。

## 六、技术架构

### 分层结构

系统采用前后端一体的单模块 Spring Boot 工程，自上而下分为入口层、AI 核心层、业务模块层、AI / 外部服务层与数据层：浏览器静态页面经鉴权拦截器进入后端；AI 核心层负责流式对话、工具调用、记忆与 RAG 编排；业务模块层承载护理、商城、社区、简报等能力；数据层由关系型主库承担业务数据、由本地向量库承担检索数据。

### 技术栈

| 维度 | 内容 |
| --- | --- |
| 语言 / 框架 | Java 21 · Spring Boot 3.5.14 · Spring MVC · Spring AI 1.0.9 |
| 工程形态 | 单模块 Maven 工程（`com.example.demo`） |
| 数据存储 | MySQL 8（业务主库）+ SQLite（RAG 向量库） |
| 对话模型 | DeepSeek（OpenAI 兼容接口） |
| 多模态 / 语音 | qwen-vl 视觉识别 · qwen-image 生图 · 讯飞 TTS · DashScope ASR |
| 外部服务 | 心知天气 · 高德地图 · 百度搜索 · WebPush |
| 前端 | 原生 HTML / CSS / JavaScript，SSE 流式渲染 |
| 部署 | 阿里云服务器 + Nginx HTTPS + systemd，应用仅监听 `127.0.0.1` |

### 实现亮点

- 以 Spring AI 工具调用替代手写路由，模型自主决定是否调用工具、调用哪个工具；
- 记忆写入通过事件异步完成，同一消息对只落一次向量，并以唯一索引兜底并发重复；
- 业务提示词、RAG 上下文与滚动摘要合并为唯一 system 消息，固定顺序、互不污染；
- 区分「正式持久化记忆入口」与「单轮兼容入口」，记忆契约明确可测；
- 检索可观测接口默认关闭，需登录并命中白名单才能访问，访问行为全部审计。

## 九、应用价值

- **对用户**：把养护知识、诊断、记录、提醒与服务查询集中到一个对话入口，降低养护门槛，减少信息遗漏；
- **对技术**：完整实践了 AI Agent 工具调用、长对话记忆、私有知识库 RAG 与多用户隔离，是一套可运行、可评测、可观测的工程样本；
- **对运营**：社区、商城、库存与数据观测构成内容与业务闭环，具备持续运营与二次开发的基础。
