# 域名上线准备评估

> 评估日期：2026-09-29
>
> 结论：现在可以开始选域名、配置 DNS 和推进备案，但不建议直接把现有公网 `8080` 作为正式域名入口。

---

## 一、当前探测结果

对现有阿里云临时演示入口做过外部连通性检查：

| 端口 | 结果 | 说明 |
| --- | --- | --- |
| `8080` | 可访问并返回 HTTP 200 | 当前应用直接对外提供 Web 服务 |
| `80` | 无法连接 | 未配置标准 HTTP 入口或安全组未放行 |
| `443` | 无法连接 | 尚未配置 HTTPS 入口 |
| `3306` | 无法连接 | MySQL 未暴露到公网，保持该状态 |

因此，域名可以解析到该服务器，但在补齐反向代理和 HTTPS 之前，标准域名访问不可用；若使用 `域名:8080` 临时访问，会带来备案、Cookie 安全、浏览器提示和暴露面问题，不适合作为正式方案。

---

## 二、当前代码侧准备度

已经具备：

- Session 鉴权、401 统一响应、登录失败限流。
- CORS 显式白名单。
- Cookie `HttpOnly`、`SameSite=Lax`，支持通过环境变量开启 Secure。
- 6 个上传模块、7 个上传接口方法的扩展名、大小和文件内容校验。
- `Origin` / `Referer` 跨站请求校验。
- 图片上传使用服务端 UUID 文件名，原始文件名不再进入物理路径。
- 基础安全响应头。

仍不具备正式域名上线条件：

- 尚未选择具体域名，无法配置 DNS 和证书。
- 未确认服务器 ICP 备案状态。
- 未验证服务器上的 Nginx / Caddy 等反向代理。
- `80/443` 当前不可访问。
- 生产环境尚未设置真实域名对应的 CORS 和 Secure Cookie。
- 旧密钥轮换按当前决策暂缓；公开上线前不能长期保持该状态。

---

## 三、推荐上线架构

```text
浏览器
  |
  | HTTPS 443
  v
Nginx / 反向代理
  |
  | 仅内网访问 127.0.0.1:8080
  v
Spring Boot
  |
  +-- MySQL 127.0.0.1:3306
  +-- uploads 文件目录
  +-- SQLite 向量库
```

公网只开放 `80/443`，应用端口、数据库端口和管理端口不对公网开放。

---

## 四、执行步骤

1. 选定主域名，例如 `example.com`，并确定是否同时使用 `www`。
2. 完成域名实名和解析，配置 A 记录指向生产服务器公网 IP。
3. 若服务器位于中国大陆，按接入商要求提交 ICP 备案；备案通过前不要正式开放域名 Web 服务。
4. 在服务器安装并配置 Nginx / Caddy。
5. 让反向代理转发到 `127.0.0.1:8080`，保留真实 Host、协议和客户端 IP。
6. 配置 TLS 证书和自动续期，开启 HTTP 到 HTTPS 跳转。
7. 设置生产环境变量：

```properties
APP_CORS_ALLOWED_ORIGINS=https://example.com,https://www.example.com
SESSION_COOKIE_SECURE=true
```

8. 将应用监听端口限制为本机访问，云安全组关闭公网 `8080`。
9. 验证登录、上传、SSE 流式聊天、图片访问和 WebPush。
10. 增加限流、日志、备份和回滚验证。

---

## 五、反向代理关键点

- 上传大小：与应用保持一致，当前为 `10MB`。
- 流式接口：对 `/api/ai/chat/stream` 关闭缓冲，避免 SSE 输出被阻塞。
- 超时：普通 API 与长时间 AI 请求分开配置。
- 转发头：保留 `Host`、`X-Forwarded-For`、`X-Forwarded-Proto`。
- 日志：不得记录 Cookie、Authorization、请求体或真实密钥。
- 健康检查：提供仅反向代理可访问的本地健康检查地址。

---

## 六、最终判断

域名工作可以启动，但不是“买完域名立刻替换 IP”即可完成。正式发布需要同时满足：

1. 域名、DNS 和备案条件明确。
2. Nginx / Caddy 反代可用。
3. `80/443` 和 HTTPS 证书配置完成。
4. CORS、Secure Cookie、HTTPS 跳转和端口收敛完成。
5. 旧密钥完成轮换。

在上述条件完成前，可以继续用现有 IP 做内部演示，但不建议对外宣传为正式域名服务。
