## 一、背景与目标

阶段 4.4 完成 Phase A/B 后，依赖漏洞从 149 条降到 16 条，剩余：

- **4 条 CRITICAL**：`spring-webmvc` / `spring-webflux` 6.2.19。6.2.x 线不再修复，只有 Spring Framework 7.0.9+ 修复。
- **2 条 HIGH**：`async-http-client` 2.16.1（`web-push` 传递依赖），只有 3.0.14 修复。
- 其余为 MEDIUM/LOW，含 POI 5.2.5 与 commons-compress 1.25.0 的中危项。

Spring AI 2.x 的 starter POM 明确按 Spring Boot 4.1.2 构建，**Spring AI 2 与 Boot 4 必须同批升级**，否则自动配置类引用的 Boot 包不存在，应用上下文无法启动。

**目标**：

1. 升级到 Spring Boot 4.1.2 / Spring Framework 7.0.10 / Spring AI 2.0.2 / POI 6.0.0。
2. 清除 4 条 Spring Framework CRITICAL。
3. 在独立分支完成编译、全量测试、本地冒烟和 OSV 复扫。
4. 修复升级过程中确认的 `AssistantMessage.toString()` 文本提取缺陷。

**非目标**：

- 不部署、不灰度、不连接生产、不改生产 systemd/Nginx/数据库。
- 不合并 main、不建“已就绪”PR。
- 不升级 OkHttp 5（见 §六）、不升级 AHC 3、不动 DashScope 2.23.3。
- 不启用阶段 3.4 的 rerank / compression 开关（保持 false）。
- 不引入 Spring Security starter，不替换自研 CSRF / Session / RAG / 记忆。

## 三、影响面

### 3.1 Spring AI（代码面小）

全仓库只有 7 个文件直接引用 `org.springframework.ai.*`：

- `Application.java`：排除 `ChatMemoryAutoConfiguration`（2.0.0 中包路径未变，暂不改）。
- `ai/SpringAiChatService.java`、`care/service/SpringAiCareWorkflowService.java`、`care/service/MedicalTriageService.java`：`ChatModel.call(Prompt)` + `ChatResponse.getResult().getOutput()`。
- `ai/ToolCallingService.java`、`ai/SpringAiTools.java`、`weather/service/WeatherService.java`：只把 `@Tool/@ToolParam` 当元数据反射读取，不经过 Spring AI 工具执行链。

未使用 `ChatClient`、`EmbeddingModel`、Spring AI `VectorStore`、`Advisor`、Spring AI `ChatMemory`、`DocumentReader`；RAG、向量库、对话记忆全部为自研实现。

**已确认缺陷**：3 处 `getOutput().toString()` 拿到的是 `AssistantMessage.toString()` 调试串，不是纯文本。`MedicalTriageService` 将其当 JSON 解析，必然失败并固定返回 MEDIUM。统一改为 `getText()`。

### 3.2 Spring Boot / Framework

- Web：`WebMvcConfigurer`、`HandlerInterceptor`、`OncePerRequestFilter`、`SseEmitter`、`forward:` 静态页在 Framework 7 中 API 未变。
- 数据：双数据源（MySQL + SQLite），两个 EMF / 事务管理器 / JdbcTemplate；Hibernate 7 仍提供 `MySQLDialect` 与 community `SQLiteDialect`。
- 安全：无 Spring Security starter，仅 `spring-security-crypto` 的 BCrypt；CSRF/Session 自研。
- 序列化：无自定义 `ObjectMapper`、无 Jackson 注解；HTTP JSON 完全依赖 Boot 默认（Boot 4 默认 Jackson 3）。
- 异步/定时：`@Async`、`@Scheduled`、`ThreadPoolTaskExecutor`、`CompletableFuture.runAsync`。
- 无 Actuator、无 RestTemplate/RestClient/WebClient 直接使用；外部 HTTP 走 OkHttp / HttpClient5 / JDK HttpClient / AHC。
- `jakarta.*` 已全部就位，无 `javax.servlet` / `javax.persistence` 残留。

### 3.3 序列化与数据库行为

高风险但不是编译错误，必须回归：

- Jackson 3 对 `LocalDateTime`、null 字段、record、`Map<String,Object>`、SSE data 的默认行为。
- fastjson2 `JSONObject` 嵌入 Jackson 响应时仍按 Map 语义输出。
- Hibernate 7 对双 EMF、`ddl-auto=update`、原生 UNION / `DELETE ... LIMIT` / `@Lock` 的行为。
- Hikari 7 下 SQLite `connectionInitSql` 的多条 PRAGMA 是否仍生效。

### 3.4 Web Push 与 Netty

`web-push 5.1.2` 传递 `async-http-client 2.16.1`，其按 Netty 4.1.136 构建；Boot 4 使用 Netty 4.2.19。需要本地 HTTP 传输验证；真实推送需浏览器订阅，本轮至少验证 AHC 在 Netty 4.2 下可加载并发请求。
