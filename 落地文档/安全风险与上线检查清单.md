## 三、端口与网络基线

公网只开放：

- `22`：尽量限制来源 IP，或改用云厂商安全组跳板 / 堡垒机。
- `80`：仅用于跳转 HTTPS，证书续期校验按实际方案开放。
- `443`：正式 Web 入口。

不得对公网开放：

- `8080`：只允许反向代理通过 `127.0.0.1` 访问。
- `3306`：MySQL 仅监听本机或内网。
- 调试、管理、监控和临时测试端口。

## 四、部署配置检查

生产环境至少设置：

```properties
APP_CORS_ALLOWED_ORIGINS=https://实际域名
SESSION_COOKIE_SECURE=true
MYSQL_PASSWORD=由部署环境注入
```

如服务器前面有 Nginx 或其他反向代理，确认应用已启用转发头处理：

```properties
server.forward-headers-strategy=framework
```

反向代理需要处理：

- `client_max_body_size` 与应用上传上限保持一致，当前为 `10MB`。
- SSE 流式接口关闭代理缓冲，保证聊天流式输出不被缓存。
- 为普通接口设置合理超时，为长时间 AI 请求单独设置更长超时。
- 不在代理访问日志中打印 Cookie、Authorization 或请求体。

## 五、发布前验收

- [ ] 仓库和构建产物中不存在真实密钥。
- [ ] 外部服务密钥已完成轮换，旧密钥已失效。
- [ ] `80` 可跳转 `443`，证书链有效，Cookie 为 Secure。
- [ ] 公网无法直接访问 `8080` 和 `3306`。
- [ ] 未登录访问受保护接口返回 401，登录后可正常使用。
- [ ] 跨站 Origin 请求被拒绝，正常域名请求可通过。
- [ ] 空文件、伪造扩展名、超过 10MB、损坏 PDF / DOCX 均被拒绝。
- [ ] 登录失败限流生效，错误信息不泄露账号是否存在。
- [ ] 备份、回滚、日志查看和数据库恢复流程已验证。
