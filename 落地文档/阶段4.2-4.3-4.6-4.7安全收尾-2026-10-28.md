## 二、交付内容

### 2.1 全局限流（4.2 / S-02）

- 位置：`/etc/nginx/conf.d/ilink-rate-limit.conf` + 站点配置。
- 按 IP + 路径分 zone：登录 12r/m burst 10、注册 6r/m burst 3、AI/SSE 30r/m burst 10、上传 20r/m burst 8、通用 API 300r/m burst 60。
- SSE 使用独立 location，保留 `proxy_buffering off` 与 600s 超时。
- 429 返回 JSON：`{"code":429,"message":"请求过于频繁，请稍后再试","data":null}`。
- 实测：15 次登录请求中前 12 次正常、后 3 次 429，响应体正确。
- 注意：nginx 1.18 的 `limit_req_dry_run` 只写 debug 日志，默认不可见，因此直接生效并采用宽松阈值。

### 2.2 上传与解析保护（4.3 / S-04）

- `/uploads` 静态资源绕过鉴权已修复：`static-locations` 只保留 `classpath:/static/`，上传文件只经受登录拦截器保护的 `/uploads/**`。
- 解析统一走 2 线程有界池 + 信号量 + 45s 超时：
  - PDF 限 200 页、50 万提取字符，使用临时文件缓存；
  - DOCX 限 2 万段落、50 万字符，解压上限降到 25MB；
  - 文本同样限 50 万字符。
- 文件问答 prompt 截断 3 万字符、问题限 1000 字符；文生图 prompt 限 4000 字符。
- `/api/care/identify` base64 增加大小、编码、magic-byte 校验。
- 出网超时：Vision 5s/60s、ImageGen 5s/120s + 20MB 下载上限、LLM 5s/2s/90s。
- ffmpeg：统一 `runFfmpeg()`，`-nostdin -t 300 -threads 1`，超时 `destroyForcibly`，修复先读管道再 waitFor 的死锁；并发 1。
- KB：分块上限 2000、超长段落正确切分、导入并发 1。
- Agent `analyzeFile` 只允许 uploads 内文件与公网 HTTP(S)，拒绝绝对路径、`file:///` 任意位置、`data:`、回环/内网/169.254.169.254；禁重定向，下载 5MB 上限。

### 2.3 关键操作审计（4.6）

- 新表 `operation_audit_log`（MySQL，启动时由 `CareSchemaInitializer` 建表），含 trace_id、user_id、client_ip、action、outcome、target、method/path、UA、created_at 及索引。
- `AuditContextFilter` 生成 `traceId` 写入 MDC 并回写 `X-Trace-Id`。
- 埋点：登录成功/失败/锁定、注册、注销、KB 上传/删除、商品发布/删除、社区删帖、护理目标删除、文件处理/问答、ASR、识图类接口、base64 识别。
- `ClientIpResolver` 优先 `X-Real-IP`，否则取 XFF 最后一个；登录失败计数同步改用该值。
- 保留 365 天，每日 04:45 清理；`APP_AUDIT_ENABLED=false` 可一键关闭。
- 实测 5 条冒烟审计记录的 trace_id 与响应头一致，client_ip 为真实公网地址。
