## 一、盘点结论

前端共 17 个 HTML 页面，合计约 370KB。服务端 `PageController` 映射 12 个路由；`index.html` 由 Spring Boot 欢迎页机制挂在 `/`；其余 4 个功能页没有服务端路由，只能通过静态资源路径直达。

补充事实：

- 鉴权拦截器只覆盖 `/api/**` 与 `/uploads/**`；页面层没有服务端鉴权，`guard.js` 仅在接口返回 401 时把浏览器跳到登录页。
- `disease` / `inventory` / `timeline` / `community` 四个页面共约 213KB，占前端总量约 58%，且都是「静态页 + 自用 API」结构。
- `inventory` 是唯一被其他页面复用的非核心 API：`home.html` 读取 `/api/inventory/items` 显示库存计数。
- `shop` 相关 API 由 `shop.js` 与 `shop-publish.html` 使用；`shop.html` 本身几乎不含业务脚本。
- 2026-10-31 的问卷报告结论是「下一阶段应以真实任务完成率、再次使用率和来源点击率验证产品，而不是继续扩张功能」。

## 二、核心路径

路线图定义的核心路径是：**提问 → 记忆检索 → 工具调用 → 有依据的回答**。

对应入口建议保留：

| 层级 | 页面 | 理由 |
| --- | --- | --- |
| 入口 | `login` / `register` / `index` | 登录注册与首屏 |
| 导航 | `home` | 统一入口，需随下线项同步瘦身 |
| 核心 | `chat` | 主对话、记忆、工具、引用来源 |
| 核心 | `care` | 护理问答、识图、档案 |
| 闭环 | `reminders` | 护理提醒，与「记录 → 提醒」闭环直接相关 |
| 支撑 | `kb` | 知识库维护，仅管理员写入 |
| 支撑 | `stats` | 运行观测 |
| 支撑 | `briefing` / `gallery` | 体量小、入口稳定，可保留观察 |

## 三、下线候选（按建议优先级）

### 3.1 社区 `community.html`（建议下线）

- 76.4KB，前端最大页面；无服务端路由；API 仅被自身使用。
- 不在核心路径上，且社区运营需要独立的内容与审核成本，当前没有运营机制。
- 下线动作：移除 `home.html` 卡片、删除页面；`CommunityController` 与相关表保留到阶段 6 统一处置。

### 3.2 成长时间线 `timeline.html`（建议下线）

- 52.9KB；无服务端路由；API 仅被自身使用。
- 与 `care` 的护理档案存在信息重叠，核心价值可由护理记录承接。
- 下线动作同 3.1。

### 3.3 病害诊断 `disease.html`（建议合并后下线）

- 42.0KB；无服务端路由；`/api/disease/diagnose` 与 `care` 的 `/api/care/identify` 功能重叠。
- 建议先确认 `care` 的识图能力覆盖现有诊断场景，再把入口收敛到 `care`，避免同名能力两套入口。

### 3.4 智能库存 `inventory.html`（建议下线或并入提醒）

- 42.2KB；无服务端路由；仅 `home` 复用其计数接口。
- 若下线，需要同步移除 `home.html` 的库存卡片与计数请求；补货提醒可并入 `reminders` 或后续统一提醒中心。

### 3.5 商城 `shop` / `shop-publish`（待产品决策）

- 页面体积不大，但包含商品、分类、上下架等完整电商链路，属于独立业务范围。
- 当前核心路径不依赖它；保留会增加维护面，下线会改变产品定位，需要明确取舍。

### 3.6 保留观察项

`briefing`、`gallery`、`kb`、`stats` 体积小、职责单一，暂不列入下线；阶段 5.2 再评估是否合并入口。

## 四、风险与约束

- 下线页面不影响 `/api/**` 的鉴权与数据；后端接口和表的清理属于阶段 6，不在本阶段删除。
- 四个无路由页面目前靠静态路径直达，下线后不会留下服务端 404 路由问题。
- `home.html` 是唯一导航汇聚点，任何下线都必须同步移除对应卡片，否则会出现死链。
- 生产 canary（阶段 3.4 重排）与本阶段互不影响；前端改动需单独发版并走现有备份/回滚流程。
- 页面层没有服务端鉴权是既有事实；本阶段下线入口不改变该模型，是否补服务端页面鉴权留到阶段 6 评估。

- `kb.html`：同样修正 `common.js` 加载顺序。
- 后端接口与数据表保留，不在本阶段删除；供阶段 6 统一处置。

保留页面（10 个）：`index`、`login`、`register`、`home`、`chat`、`care`、`reminders`、`community`、`kb`、`stats`。
