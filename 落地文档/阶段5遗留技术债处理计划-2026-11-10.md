## Context

阶段 5 已完成 UI 与产品范围收敛并上线，但收口记录留下四项技术债：

1. **README / 路线图过期**：仍写“阶段 6 进行中”，缺少阶段 6 完成与阶段 7 进行中的结论。
2. **Service Worker scope**：注册在 `/js/`，推送可用，但 `navigator.serviceWorker.ready` 在 `/home` 等页面不会 resolve，未来离线/页面缓存会被卡住。
3. **社区页未瘦身**：`community.html` 1,864 行，其中内联 CSS 1,158 行、内联 JS 604 行；约 150 行 CSS 死代码、约 55 行死 JS，并存在 Toast 被覆盖的运行缺陷。
4. **公共模块未抽取**：鉴权、API、Toast、错误处理、loading、转义分散在 7 个登录后页面；`apiFetch` 只被 2 个页面使用，全站约 46 处 `fetch`。

用户选择“全部四项，分步交付”。目标：保持纯静态 HTML/JS、无构建链，不改业务 API 与数据模型；每一步可独立验证、提交、回滚。

## 约束

- 不引入前端框架、打包器、ES Module 或 `defer` 加载。
- 不把页面脚本改成 IIFE；社区页 25 个内联 `onclick` 依赖全局函数。
- 不改 `/api/**` 契约、响应字段、数据库和鉴权语义。
- 公共层全局名称避开页面已有的 `let/const`（`currentUser`、`toolMode` 等）。
- 本轮只做本地验证；生产部署另行确认。
- 所有改动静态资源统一 bump `?v=20261110a`（分次部署时按发版窗口递增）。

## 阶段 1：公共层基础（只加能力，不迁页面）

文件：`js/common.js`、`js/shell.js`、`css/ui.css`、`css/pages.css`

设计：

- 保留现有全局 `showToast` / `toast` / `apiFetch` / `requireLogin` / `logout`，新增 `window.UI` 命名空间；旧名作为薄包装，避免 47 个 `onclick` 失效。
- `UI.me()`：memoized `/api/auth/me`，返回完整信封 `{code,data}`；失败清缓存，允许重试。
- `UI.requireLogin(cb)`：沿用现有回调契约，`cb(data)`；跳转加单次标志，避免与 `guard.js` 重复导航。
- `UI.apiFetch`：合并 headers；对象 body 自动 JSON；`FormData` / `Blob` / `URLSearchParams` 不设 Content-Type；401 默认跳登录并可关闭。
- `UI.apiJson`：在 `apiFetch` 上解析 JSON；**不强制检查 `code/success`**，保留各页现有分支。
- `UI.toast(msg, opts)`：`opts` 支持数字毫秒或 `'success'/'error'/'info'`；统一 `#app-toast` + `ui.css` 的 `.ui-toast`；加 `role="status"` / `aria-live="polite"`。
- `UI.setBusy(target, busy, {text})`：禁用、`aria-busy`、可选替换文本、恢复原文；只用于文本按钮。
- `UI.escapeHtml` / `UI.escapeAttr`：统一 `& < > " '`。
- `shell.js` 删除独立 `/api/auth/me` 请求，改由 common 在加载后调用一次 `UI.me()` 填充侧栏；7 页每页最多一次 me 请求。
- 把 `common.js` 运行时注入的 `.msg-sources` 样式迁入 `pages.css`，删除 `ensureSourceStyles` 的运行时注入。
- `ui.css` 增加 `.ui-toast` 及类型变体。
- 同步把引用 `common.js` / `shell.js` / `ui.css` / `pages.css` 的 10 个 HTML 的 `?v=` 升到 `20261110a`（7 个登录页 + index/login/register）。

验证：`node --check`；现有测试；7 页截图不变；每页 Network 中 `/api/auth/me` 只有一次；连续两次 `UI.me()` 只发一次请求。

## 阶段 6：Service Worker 方案 C

文件：`SecurityHeadersFilter.java`、`SecurityHeadersFilterTest.java`、`common.js`、`push.js`、`home.html`

后端：

- 对精确路径 `/js/service-worker.js` 设置 `Service-Worker-Allowed: /` 和 `Cache-Control: no-cache, must-revalidate`；放在现有 `/js/` 排除逻辑之前。
- 测试：该路径有头；`/js/push.js` 无该头；`.map` 或其他 `/js/*` 无该头。

前端：

- 注册改为 `register('/js/service-worker.js', { scope: '/' })`；捕获 `SecurityError` 降级到默认 `/js/`，兼容滚动发布。
- `home.html` 两处 register 同步；`getRegistration('/')` 修正当前传脚本路径的错误。
- `UI.sw` 统一 `path/scope/register/getRegistration/reconcileLegacy`；VAPID 公钥只保留一处。
- 迁移旧 `/js/` registration：若旧订阅存在，先在新 `/` registration 订阅并 POST 新 endpoint，成功后 DELETE 旧 endpoint、`oldSub.unsubscribe()`、`legacy.unregister()`；新订阅失败则保留旧 registration，下次重试，避免推送中断。
- `push.js` 和 home 的推送开关都改用 `UI.sw.getRegistration()`。

验证：`./mvnw -B -Dtest=SecurityHeadersFilterTest test`；`curl -I` 检查响应头；DevTools 中只有一条 scope `/` 的 registration；`navigator.serviceWorker.ready` resolve；推送订阅/退订与测试推送只收到一条通知；刷新两三次不重复创建 registration。

回滚：后端 header 可保留；回滚前端注册后旧代码会走 `/js/`。已在浏览器的 `/` registration 可在 DevTools 一次性 unregister；此操作会临时丢失推送，需重新订阅。
