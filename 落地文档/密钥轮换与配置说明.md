# 密钥轮换与配置说明

> 整理日期：2026-09-11
>
> 文档定位：记录敏感配置的外置方式、轮换顺序和验证要求。
>
> 安全说明：本文只记录配置键和环境变量名，不记录任何真实密钥、账号、密码或公网地址。

---

## 一、当前结论

- 受版本控制的 `application.properties` 已恢复为环境变量占位符。
- 本地开发使用被 Git 忽略的 `application-local.properties`。
- `application-local.properties` 已确认被 `.gitignore` 忽略。
- 仓库配置了远程地址，且历史提交中存在密钥特征，因此历史中出现过的密钥统一按已泄露处理。
- 历史重写不自动执行，必须完成密钥轮换并协调所有开发者后，再决定是否清理 Git 历史。

---

## 二、配置外置原则

1. 受版本控制的配置文件只允许保存环境变量引用、非敏感默认值和功能开关。
2. 本地真实配置只放在 `application-local.properties` 或 `.env` 等忽略文件中。
3. 生产环境优先使用操作系统环境变量、容器 Secret 或密钥管理服务。
4. 密钥不得写入日志、接口响应、异常信息、测试数据或部署文档。
5. 同一密钥只能有一个明确来源，避免本地文件、环境变量和 CI 配置互相覆盖后难以排查。

Spring Boot 不会自动加载 `.env`。`.env.example` 仅用于说明部署工具所需的变量；本地 Spring Boot 配置使用 `application-local.properties`。

## 四、本地配置步骤

1. 将 `application-local.properties.example` 复制为 `application-local.properties`。
2. 在本地忽略文件中填入真实配置。
3. 确认 `application-local.properties` 不会出现在 `git status` 中。
4. 每次修改配置后运行：

```powershell
.\scripts\check-sensitive-config.ps1
```

5. 启动应用并验证模型、数据库、天气、地图、语音和搜索相关功能。

---

## 五、密钥轮换流程

所有历史中已出现的密钥按以下顺序处理：

1. 在服务商控制台创建新密钥。
2. 将新密钥写入本地忽略配置或部署环境的 Secret。
3. 重启应用并验证对应功能。
4. 观察日志和错误率，确认不再使用旧密钥。
5. 撤销旧密钥。
6. 在本文末尾的轮换记录中更新日期、负责人和验证状态。

禁止先撤销旧密钥再更新应用，避免服务中断。

### 特殊说明

- MySQL 密码轮换需要维护窗口，并同步更新数据库连接配置。
- WebPush 私钥更换后必须同步更换公钥，已有浏览器订阅需要重新创建。
- 讯飞 TTS 的 App ID、API Key 和 API Secret 需要一起核对。
- 百度搜索、高德和天气密钥应同时检查控制台中的域名、IP 或额度限制。
- 如果配置值包含特殊字符，优先使用操作系统环境变量，避免属性文件转义问题。

## 六、Git 历史处理

完成密钥轮换后，如果决定清理历史，可使用 `git filter-repo` 或 BFG。该操作会重写提交历史，并要求所有协作者重新克隆或同步，因此必须满足以下条件：

1. 所有已暴露密钥均已轮换。
2. 远程仓库维护者已同意强制推送。
3. 所有协作者已知晓重新同步要求。
4. 已保留必要的迁移和回滚方案。

历史重写不是配置外置的替代方案。
