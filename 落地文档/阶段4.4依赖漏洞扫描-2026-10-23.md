## 二、扫描工具与周期

### 本地

```bash
mvn -B -ntp dependency:list -DincludeScope=test \
  -DoutputFile=target/dependency-list.txt
mvn -B -ntp -f TEST/pom.xml dependency:list -DincludeScope=test \
  -DoutputFile=target/dependency-list.txt
python scripts/osv_scan.py \
  --dependency-file target/dependency-list.txt \
  --dependency-file TEST/target/dependency-list.txt \
  --baseline .osv-baseline.json \
  --fail-on high
```

### CI

- `.github/workflows/dependency-scan.yml`：push、PR、每周一 03:17（Asia/Shanghai）和手动触发。
- 命中新的 HIGH/CRITICAL 时 CI 失败，并上传 `osv-report.txt`。
- `.github/dependabot.yml`：每周为根工程、`TEST/` 和 GitHub Actions 创建升级 PR，按 Spring / 测试依赖分组。

### 基线

`.osv-baseline.json` 记录了本次已接受的 149 条发现。CI 只对**新增**的 HIGH/CRITICAL 失败，避免首次接入就让主干全红。

基线不是永久豁免：

- 每月复核一次；升级后重新生成，只保留确认仍存在且暂不处理的项目。
- 目标是把 CRITICAL 清零；新增 CRITICAL 应在 48 小时内分诊，HIGH 在一周内分诊。
- 修改基线必须走 PR，并在 PR 描述里写清接受理由和复核日期。

## 三、CRITICAL 明细与处置

### 3.1 Tomcat（6 条，可通过覆盖修复）

当前 `tomcat-embed-core:10.1.54`。Boot 3.5.16 默认给 10.1.55，仍有 3 条需要 10.1.58+；建议在 `pom.xml` 覆盖：

```xml
<tomcat.version>10.1.61</tomcat.version>
```

涉及：安全约束未正确应用、DIGEST/FORM 认证绕过、HTTP/2 请求头校验。应用使用 Session 登录、未使用 Tomcat FORM/DIGEST，公网 HTTP/2 由 Nginx 终止，实际暴露面较低，但仍应升级。

### 3.2 Netty（1 条）

`netty-handler:4.1.132.Final` 的 SNI 路由绕过。Boot 3.5.16 给 4.1.135，仍低于修复版本 4.1.137；建议覆盖：

```xml
<netty.version>4.1.139.Final</netty.version>
```

Netty 主要由 WebClient / Reactor Netty 使用，需回归外部 HTTP 调用（DashScope、天气、TTS、搜索）。

### 3.3 BouncyCastle（2 条）

`bcprov-jdk18on:1.78.1` 直接升级到 `1.86`。该库只被 Web Push 的 ECC 路径使用，回归推送即可。

### 3.4 async-http-client（2 条）

来自 `nl.martijndwars:web-push:5.1.1`：

- 升级 `web-push` 到 `5.1.2`（async-http-client 2.12.4、jose4j 0.7.9）。
- 在 `dependencyManagement` 覆盖 `async-http-client:2.16.1`、`jose4j:0.9.7`，并排除 `bcprov-jdk15on`。
- 需要验证 Web Push 的 VAPID 签名和发送；如果推送功能实际未使用，评估移除 `web-push` 依赖。

jose4j 0.7.9 仍带 2 条 HIGH，0.9.7 已无公开漏洞，但跨越 0.7 → 0.9 需要回归签名/验签。

### 3.5 Spring Framework（4 条，6.2.x 无修复）

`spring-webflux` / `spring-webmvc:6.2.18` 的 3 个 GHSA（合计 4 条记录）在 6.2.x 的最后版本 `6.2.19` 仍标记为受影响，只有 `7.0.9` 修复。代码检查：

- 未发现 `RouterFunction` / `RouterFunctions` / `coRouter`，WebFlux 函数式端点绕过不适用。
- 未发现 `XsltView` / XSLT 使用，路径限制问题不适用。
- SSE 使用 `SseEmitter` 直接写事件，不经过 Spring 的 fragment 渲染，SSE 流损坏问题的实际触发面待确认。

因此**暂按低可达性接受**，但必须列为 Boot 4 迁移的驱动项；不能把“无修复”当作已解决。

## 六、升级流程与责任边界

1. Dependabot 每周一创建 PR；CI 跑构建、密钥扫描和依赖扫描。
2. 补丁升级由仓库维护者在一周内处理；大版本升级单独立项，不自动合并。
3. 每次升级必须记录：变更版本、漏洞编号、测试结果、回滚方式。
4. 涉及 RAG/Embedding/LLM 的升级，必须跑 12 题冒烟；影响检索或回答链路的再跑 40 题正式题库。
5. 生产发布仍按既有流程：备份 → 部署 → 健康检查 → 功能验证 → 收尾；保留上一版 JAR。
6. 每月复核 `.osv-baseline.json`，季度做一次依赖盘点。

## 七、限制与说明

- OSV 聚合公开 advisory，不等于完整 NVD 覆盖；Dependabot 告警作为第二来源。
- 传递依赖的版本由 BOM 决定；覆盖版本后必须重新解析并跑回归，不能只看脚本通过。
- Phase A 已改 `pom.xml` 并单独提交；Phase B/C 仍需单独提交和完整验证。
- 当前仓库仍为 public，依赖扫描不涉及凭据；4.1 的密钥暴露问题仍未关闭。
